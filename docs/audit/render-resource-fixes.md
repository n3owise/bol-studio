# Renderer resource admission follow-up

Implemented on 2026-10-10 after the independent second audit found that per-file media limits did not bound combined scene decoding.

The renderer probes visible media before allocating compositor canvases, loading images, or starting encoder/video decoder processes. It rejects more than 64 visible visual assets (including the primary video), more than eight simultaneous video decoders, or more than 24 million admitted RGBA frame pixels. Configuration uses `BOL_MAX_RENDER_VISUAL_ASSETS`, `BOL_MAX_RENDER_VIDEO_DECODERS`, and `BOL_MAX_RENDER_DECODED_PIXELS`; invalid values fail closed.

The pixel calculation includes the output canvas, every image at its native decoded dimensions because images remain preloaded, and the maximum overlap of decoded video frames including the primary. Video streams fit both output width and output height and do not upscale sources. Placed video scale also limits overlay decode width. FFmpeg streams start when the placement becomes active and close, with process exit awaited, before later placements start. Thus sequential videos reuse admission instead of all retaining decoder processes for the entire export. Timings use integer frame ranges; the existing inclusive placed end time can overlap the following placement for one frame and is counted accordingly.

Resource admission errors emit only the fixed stdout code `render_resource_limit`, exit unsuccessfully, and retain an actionable explanation on stderr. The API maps that code to a fixed safe user-facing instruction to lower resolution, use smaller images, or reduce overlapping videos; ordinary processing failures retain their separate generic handling.

Verification: eleven focused Node tests passed, including the existing scene ordering, overlay progression/looping and primary final-frame holding tests. Tests exercise 8K/tall scaling, configurable bounds, primary/output inclusion, native image accounting, sequential clips, one-frame overlaps, and actual FFmpeg tall-video decoding. An integration test invokes the real renderer CLI with excessive overlapping videos and a deliberately nonexistent encoder path: it returns the resource code before invoking that encoder and creates no output file. Type checking passed. Evidence: `evidence/render-resource-tests.txt`.

Limits: RGBA admission is a compositing budget, not a measured process-RSS ceiling. Codec-internal buffers, canvas implementation copies, image-decoding temporary buffers, Remotion/Chromium memory and CPU costs remain additional. Image native pixel accounting prevents large compressed images from bypassing this budget, but admitted images are not downsampled before loading. A configured larger budget deliberately increases resource exposure. Real full-scene export verification is recorded by the coordinating agent; these focused checks do not establish 4K throughput or a load-test guarantee.
